<h1>Portfólio de Projetos Pessoais – Desenvolvimento de Software</h1>

<p>Este repositório tem como objetivo principal a centralização e organização de projetos pessoais desenvolvidos com foco na construção de um portfólio profissional na área de desenvolvimento de software.
Os projetos aqui presentes representam estudos práticos, experimentações, desafios técnicos e aplicações reais criadas ao longo do processo de aprendizagem e evolução como desenvolvedor.</p>

<p>A proposta deste repositório é servir como um histórico de evolução técnica, demonstrando desde conceitos básicos de programação até soluções mais completas envolvendo arquitetura de sistemas, lógica de negócio, persistência de dados e integração entre camadas.
Grande parte dos projetos é pensada sob a ótica de <strong>desenvolvimento Full Stack</strong>, abrangendo tanto o front-end quanto o back-end, sempre que possível.</p>

<p>Cada projeto possui sua própria pasta, contendo descrição, tecnologias utilizadas, instruções de execução e, quando aplicável, exemplos de uso.
As tecnologias abordadas podem variar, incluindo (mas não se limitando a): JavaScript, TypeScript, Node.js, HTML, CSS, bancos de dados relacionais e não relacionais, frameworks modernos e ferramentas de versionamento.</p>

<p>Este repositório não tem caráter comercial, mas sim educacional e demonstrativo, sendo utilizado como material de estudo, referência e apresentação profissional.
Os códigos podem conter diferentes abordagens para o mesmo problema, justamente para evidenciar a evolução do raciocínio e das boas práticas ao longo do tempo.</p>

<p>O objetivo final é consolidar um portfólio consistente, que reflita habilidades técnicas, capacidade de resolução de problemas, organização de código e entendimento de conceitos fundamentais da engenharia de software.</p>

<h2>Gestão de Versão</h2>
<p>A gestão de versão ocorrerá por projeto seguindo o padrão <strong>SemVer (Semantic Versioning)</strong>, no formato:</p>
<p><strong>MAJOR.MINOR.PATCH</strong></p>

<ul>
  <li><strong>MAJOR</strong>: mudanças grandes que quebram compatibilidade ou reestruturação geral.</li>
  <li><strong>MINOR</strong>: adição de novos projetos ou funcionalidades sem quebrar compatibilidade.</li>
  <li><strong>PATCH</strong>: correções de bugs, refatorações e pequenos ajustes.</li>
</ul>

<p>
Exemplo: <code>v1.2.3</code><br>
1 → versão principal do portfólio<br>
2 → novos projetos adicionados<br>
3 → correções e melhorias internas
</p>
